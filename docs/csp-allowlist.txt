==============================================================================
부트페이 결제 연동 — Content-Security-Policy(CSP) 허용 도메인 안내
==============================================================================

결제 버튼을 눌렀는데 아무 일도 일어나지 않는다면, 대부분 이 문서의 문제입니다.
브라우저 개발자도구(F12) 콘솔에 아래와 비슷한 빨간 줄이 있는지 먼저 확인하세요.

    Refused to frame 'https://...' because it violates the following
    Content Security Policy directive: "frame-src ..."

이 메시지가 보이면 부트페이 장애도, 연동키(Client Key) 문제도 아닙니다.
고객사 웹서버가 내보내는 보안 헤더(CSP)가 결제창을 막고 있는 것입니다.

※ CSP 를 설정한 적이 없다면 이 문서는 필요 없습니다. 결제창은 그냥 뜹니다.

──────────────────────────────────────────────────────────────────────────────
1. 가장 빠른 해결 — frame-src 에 아래 값을 넣으세요
──────────────────────────────────────────────────────────────────────────────

결제창을 막는 지시어는 frame-src 하나입니다. (iframe-src 라는 지시어는 없습니다)
frame-src 를 아예 선언하지 않으면 default-src 로 폴백되므로,
default-src 'self' 만 있어도 똑같이 막힙니다.

──────────────────────────────────────────────────────────────────────────────
7. CSP 를 건드릴 수 없다면 — redirect 방식
──────────────────────────────────────────────────────────────────────────────

보안팀 정책이나 권한 문제로 헤더를 못 만지는 경우, 결제창을 iframe 이 아니라
페이지 이동(redirect) 방식으로 열면 frame-src 를 아예 거치지 않습니다.
즉 CSP 와 무관하게 결제가 진행됩니다.

    extra: {
      open_type: 'redirect',
      redirect_url: 'https://내도메인/payment/result',   // 필수
    }

주의 — 방식에 따라 결과를 받는 곳이 달라집니다.

    iframe / popup   →  SDK 의 confirm 콜백으로 옵니다
    redirect         →  redirect_url 페이지의 쿼리 파라미터로 옵니다
                        (event / receipt_id / order_id / status / message)

기기에 따라 방식을 나눈다면(PC=iframe, 모바일=redirect) 양쪽 처리를 모두
구현해야 합니다. 한쪽만 구현하면 그 경로의 사용자는 결과를 받지 못합니다.

참고로 모바일에서는 redirect 를 권장합니다. 결제창이 중첩 iframe 구조라
PG·결제수단·브라우저 조합에 따라 화면이 열리지 않는 경우가 있고,
그런 경우는 CSP 를 열어도 해결되지 않습니다.

──────────────────────────────────────────────────────────────────────────────
8. 그래도 막힌다면
──────────────────────────────────────────────────────────────────────────────

  1) 콘솔(F12)의 Refused to frame 문구에서 도메인을 확인해 그대로 추가
  2) curl -sI 로 실제 나가는 헤더 확인 (설정이 다른 곳에서 덮이고 있는지)
  3) 위를 다 했는데도 모바일만 안 된다면 7장의 redirect 방식으로 전환
