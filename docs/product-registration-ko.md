# 사진과 설명으로 상품 올리기 — 부트페이 MCP 상품등록 가이드

이 문서는 **판매자**를 위한 것입니다. 코드를 짜지 않고, Claude 같은 AI 앱에 말로 지시해서 쇼핑몰에 상품을 등록합니다.

개발자를 위한 결제 연동 가이드는 [README](../README.md)에 있습니다.

---

## 0. 먼저 알아야 할 것 두 가지

**① 사진은 "첨부"가 아니라 "파일 경로"로 줍니다.**

Claude 대화창에 사진을 끌어다 붙여도 그 이미지는 MCP 도구로 전달되지 않습니다. 대신 파일이 저장된 위치를 알려주세요.

```
❌ (사진을 대화창에 붙이고) "이걸로 상품 만들어줘"
✅ "~/Desktop/tshirt.jpg 로 티셔츠 상품 만들어줘, 29000원"
```

경로 확인 방법:
- **macOS**: Finder에서 파일 우클릭 → `Option` 키를 누른 채 "경로 이름 복사"
- **Windows**: 파일 우클릭 → "경로로 복사"

**② 상품 등록은 stdio(로컬 설치) 방식에서만 됩니다.**

`mcp.bootpay.ai/mcp` 같은 HTTP 주소로 연결하면 **문서 검색 도구만** 보이고 상품 등록 도구는 나타나지 않습니다. 아래 1번대로 설치하세요.

## 1. 설치

Node.js 18 이상이 필요합니다. ([nodejs.org](https://nodejs.org)에서 LTS 버전 설치)

### Claude Desktop

설정 파일을 열어 아래 내용을 넣습니다.

| OS | 설정 파일 경로 |
|---|---|
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |

```json
{
  "mcpServers": {
    "bootpay": {
      "command": "npx",
      "args": ["-y", "@bootpay/mcp"]
    }
  }
}
```

저장한 뒤 **Claude Desktop을 완전히 종료했다가 다시 실행**하세요. (창을 닫는 것만으로는 반영되지 않습니다.)

### Claude Code (CLI)

```bash
claude mcp add bootpay -- npx -y @bootpay/mcp
```

> 🔐 **설정 파일에 비밀번호나 API 키를 넣지 않습니다.** 로그인은 브라우저에서 하고, 발급된 토큰은 `~/.bootpay/` 아래에 따로 저장됩니다.

### 설치 확인

Claude에게 이렇게 물어보세요.

```
부트페이 로그인 상태 알려줘
```

`get_auth_status` 도구가 실행되면 정상입니다. "도구가 없다"고 하면 [문제 해결](#7-문제-해결)로 가세요.

## 2. 로그인 → 프로젝트 선택

```
부트페이에 로그인해줘
```

브라우저가 열립니다. 평소 쓰던 부트페이 관리자 계정으로 로그인하면 창이 자동으로 닫히고 Claude로 돌아옵니다.

```
프로젝트 선택할게
```

브라우저에 프로젝트 목록이 뜹니다. 상품을 올릴 쇼핑몰을 고르세요.

> ⚠️ **프로젝트를 반드시 확인하세요.** 여러 쇼핑몰을 운영한다면 엉뚱한 곳에 상품이 올라갈 수 있습니다. `부트페이 로그인 상태 알려줘`로 현재 프로젝트를 언제든 확인할 수 있습니다.

## 3. 첫 상품 등록

가장 단순한 형태:

```
~/Desktop/tshirt.jpg 로 상품 등록해줘.
이름은 "베이직 코튼 티셔츠", 가격 29000원.
```

Claude가 이미지를 업로드하고 상품을 만든 뒤 상품 ID를 알려줍니다.

### 옵션이 있는 상품

```
~/Desktop/tshirt-front.jpg, ~/Desktop/tshirt-back.jpg 로 티셔츠 올려줘.
29000원이고 색상은 검정/화이트, 사이즈는 M/L.
검정 L은 재고 5개, 나머지는 20개씩.
```

색상 2개 × 사이즈 2개 = **4가지 조합**이 각각 재고를 가진 항목으로 등록됩니다.

옵션별로 가격을 다르게 하려면:

```
XL 사이즈는 2000원 추가로 해줘
```

### 카테고리에 넣기

```
"상의 > 티셔츠 > 반팔" 카테고리 만들고 거기에 넣어줘
```

없는 단계만 새로 만들고 이미 있는 단계는 그대로 씁니다. 같은 말을 두 번 해도 카테고리가 중복으로 생기지 않습니다.

### 상세 이미지까지

```
대표 이미지는 ~/Desktop/main.jpg,
상세 페이지 이미지는 ~/Desktop/detail1.jpg, ~/Desktop/detail2.jpg 로 해줘
```

### 상세설명 채우기 — 블록으로 만드세요

상품 페이지를 스크롤하면 나오는 긴 설명이 **상세설명**입니다. 부트페이는 이걸 **블록**으로 쌓아 만듭니다 —
제목 한 덩어리, 본문 한 덩어리, 사진 한 덩어리 식으로 조각을 이어 붙이는 방식입니다.

```
상세설명 시작 템플릿 보여줘
```

패션·식품 같은 유형별 시작 구성을 보여줍니다. 저장해 둔 템플릿이 없어도 기본 스타터가 항상 나옵니다.

```
"패션" 템플릿으로 상세설명 만들어줘.
소개글은 "어깨선을 내려 팔을 올릴 때 당기지 않아요",
소재는 코튼 100%, 색상은 검정/화이트, 사이즈는 M/L 로 채워줘
```

템플릿에는 **빈칸 안내**가 들어 있습니다("여기에 착용컷을 올려주세요" 같은 문구).
이 안내는 편집할 때만 보이고 고객 화면에는 나가지 않습니다. **다만 채우지 않은 칸은 상세에서 그냥 빠집니다** —
템플릿을 받았으면 내용을 채운 뒤에 저장하세요.

**왜 블록인가**

| | HTML 덩어리 | 블록 |
|---|---|---|
| 모바일 | 고정폭·인라인 스타일 때문에 깨지기 쉬움 | 화면 폭에 맞춰 접힘 |
| 가격·배송비 | 바뀌면 직접 고쳐야 함 | `{{판매가}}` 토큰이 저장할 때마다 자동 반영 |
| 일부 수정 | 통째로 다시 써야 함 | 그 블록만 고치면 됨 |
| 반복되는 안내 | 상품마다 복사 | 공용 블록 하나를 여러 상품이 참조 |

HTML로 넣는 방식도 그대로 동작합니다. 다만 위 이유로 블록을 권합니다.

### 반복되는 안내는 한 번만 쓰기

배송·교환 안내처럼 모든 상품에 똑같이 들어가는 문구는 **공용 블록**으로 만들어 두면
한 곳만 고쳐도 그 블록을 쓰는 모든 상품의 상세가 함께 바뀝니다.

```
"배송·교환 안내" 공용 블록 만들어줘.
내용은 "평일 14시 이전 결제 시 당일 출고, 교환·반품은 받은 날부터 7일 이내"
```

```
그 공용 블록 쓰는 상품이 몇 개인지 보여줘
```

수정·삭제 전에 영향 범위를 먼저 확인하는 습관을 들이세요.

## 4. 자주 쓰는 문장

### 상품

| 하고 싶은 것 | 이렇게 말하세요 |
|---|---|
| 목록 보기 | `상품 목록 보여줘` |
| 검색 | `"티셔츠" 들어간 상품 찾아줘` |
| 상세 보기 | `그 상품 상세 정보 보여줘` |
| 가격 수정 | `그 상품 가격을 25000원으로 바꿔줘` |
| 사진 교체 | `그 상품 사진을 ~/Desktop/new.jpg 로 바꿔줘` |
| 전시 끄기 | `그 상품 전시 상태 꺼줘` |
| 임시저장 | `이 상품 임시저장으로 올려줘` (쇼핑몰에 안 보임) |
| 발행 | `그 임시저장 상품 발행해줘` |
| 삭제 | `그 상품 삭제해줘` |
| 테스트 상품 만들기 | `테스트 상품 5개 만들어줘` |

> 테스트 상품은 상세설명까지 블록으로 채워서 만들어집니다. `그 테스트 상품 상세 보여줘` 라고 하면
> 블록이 어떤 모양인지 실제 예시로 볼 수 있습니다.

### 상세설명

| 하고 싶은 것 | 이렇게 말하세요 |
|---|---|
| 시작 템플릿 보기 | `상세설명 시작 템플릿 보여줘` |
| 상세설명 채우기 | `그 상품 상세설명 채워줘. 소재는 코튼 100%, 세탁은 30도 손세탁` |
| 일부만 고치기 | `상세설명에서 사이즈 표만 고쳐줘` |
| 사진 넣기 | `상세설명에 ~/Desktop/detail1.jpg 넣어줘` |
| 안내 박스 추가 | `상세설명 맨 아래에 "신선식품 안내" 주의 박스 넣어줘` |
| 구독 회차 표 | `상세설명에 구독 회차 표 넣어줘` (회차 설정에서 자동으로 채워집니다) |
| 이 구성 저장 | `지금 상세설명 구성을 "우리 기본 상세"로 저장해줘` |
| 공용 블록 목록 | `공용 블록 목록 보여줘` |
| 공용 블록 만들기 | `"배송·교환 안내" 공용 블록 만들어줘` |
| 공용 블록 영향 확인 | `그 공용 블록 쓰는 상품 보여줘` |

> ⚠️ 상세설명을 **일부만** 고칠 때는 바꿀 부분만 말하면 됩니다. 언급하지 않은 블록은 그대로 남습니다.
> 다만 "상세설명 다 지워줘"는 정말로 전부 지웁니다 — 되돌릴 수 없으니 확인하고 말하세요.

### 디지털(비실물) 상품

전자책·강의·이용권처럼 배송하지 않는 상품입니다. **지급 방식**을 반드시 정해야 결제 후 구매자가 받을 수 있습니다.

| 지급 방식 | 언제 쓰나 | 함께 필요한 것 |
|---|---|---|
| 파일(`file`) | PDF·이미지 등 파일 다운로드 | 업로드한 파일 목록 |
| 링크(`link`) | 강의실 URL, 외부 서비스 | 전달할 주소 |
| 코드(`code`) | 시리얼·입장코드 | 아래 두 방식 중 하나 |
| 수동(`manual`) | 판매자가 주문마다 직접 처리 | 구매자 안내 문구 |

코드 지급은 두 가지로 나뉩니다:

- **공유 코드** — 모든 구매자에게 **같은 코드** 하나를 줍니다. 이벤트 입장코드 등.
- **개별 코드(코드풀)** — 미리 등록해 둔 번호 목록에서 **한 명당 하나씩** 꺼내 줍니다. 시리얼·라이센스.

```
전자책 상품 만들어줘. 15000원, PDF 파일로 지급.
다운로드는 3회까지, 30일 안에 받아가게 해줘
```

```
그 상품에 시리얼 번호 등록해줘. (번호 목록 붙여넣기)
```

```
그 상품 시리얼 재고 얼마나 남았어?
```

> ⚠️ **개별 코드 방식인데 코드풀이 비어 있으면 결제는 되고 지급이 실패합니다.** 판매 시작 전에 재고를 꼭 확인하세요.
> 이미 발급된 코드는 폐기할 수 없습니다.

### 카테고리

| 하고 싶은 것 | 이렇게 말하세요 |
|---|---|
| 전체 보기 | `카테고리 목록 보여줘` |
| 계층 만들기 | `"상의 > 티셔츠 > 반팔" 카테고리 만들어줘` |
| 이름 바꾸기 | `"티셔츠" 카테고리 이름을 "티셔츠류"로 바꿔줘` |
| 옮기기 | `"반팔"을 "하의" 밑으로 옮겨줘` |
| 순서 바꾸기 | `카테고리 순서를 하의, 상의 순으로 바꿔줘` |
| 삭제 | `"셔츠" 카테고리 지워줘` |

> ⚠️ 카테고리를 삭제하면 **그 아래 하위 카테고리가 전부 함께 삭제**되고 되돌릴 수 없습니다. Claude가 먼저 "이걸 지우면 하위 N개가 함께 사라집니다"라고 알려주고 확인을 받은 뒤에 지웁니다.
>
> 삭제된 카테고리에 속해 있던 **상품은 지워지지 않습니다.** 다만 그 상품은 사라진 카테고리를 계속 가리키므로, 삭제 전에 상품을 다른 카테고리로 옮겨두는 편이 안전합니다.

### 이미지만 먼저 올리기

```
~/Desktop/a.jpg, ~/Desktop/b.jpg 업로드만 해줘
```

CDN 주소를 받아둘 수 있습니다. 한 번에 **최대 10장**, 장당 **최대 10MB**, `.jpg .jpeg .png .gif .webp .bmp .avif` 만 됩니다.

### 구독(정기결제) 상품

구독 상품은 **구독 설정**이 먼저 있어야 합니다. 부트페이 관리자 화면에서 만든 뒤:

```
구독 설정 목록 보여줘
```

```
"프리미엄 멤버십" 구독 설정으로 상품 만들어줘.
3년 약정 300000원, 5년 약정 450000원.
```

- 약정 회차를 쓰면 각 회차의 기간이 1 이상이어야 합니다.
- 회차 없이 무제한 구독이면 기간을 `-1`로 둡니다. (Claude가 알아서 처리합니다)
- 구독 설정 유형이 **사용량 기반**이면 사용량 조회 API 주소가 반드시 있어야 저장됩니다.

### 배송정책 연결

```
배송정책 목록 보여줘
```

```
"기본 배송" 정책 붙여서 상품 등록해줘
```

## 5. 알아두면 좋은 것

**전시 vs 판매**
- **전시**: 쇼핑몰 목록에 보이는지
- **판매**: 장바구니·결제가 되는지

둘은 따로 놉니다. "품절이지만 페이지는 보이게" 하려면 전시는 켜고 판매를 끕니다.

**임시저장**

임시저장(`draft`) 상태의 상품은 아직 발행하지 않은 상품입니다. 사진이나 설명을 나중에 채울 때 씁니다.

저장 결과는 서버가 실제로 저장한 값으로 알려줍니다. 임시저장으로 요청했는데 발행으로 저장되면 Claude가 경고를 붙입니다(과거 이런 사례가 보고된 적이 있습니다). 노출을 확실히 막고 싶다면 전시를 함께 끄는 편이 안전합니다.

```
그 상품 임시저장으로 만들고 전시는 꺼줘
```

**재고**

재고 관리를 쓰지 않는 상품도 재고는 `0`으로 저장됩니다. 재고 값이 비어 있으면(`null`) 서버가 이후 수정 요청을 처리하지 못해 그 상품을 영영 고칠 수 없게 되기 때문에, MCP가 값을 채워 보냅니다. 재고를 쓰지 않는 상품에서 0과 빈 값은 화면상 차이가 없습니다.

수정할 때도 마찬가지로 재고를 함께 보냅니다. 재고를 지정하지 않으면 현재 값을 그대로 읽어 되돌려 보내므로 수량이 바뀌지 않습니다.

**옵션 조합**

색상 3개 × 사이즈 4개 = 12개 조합이 각각 별도 항목으로 만들어집니다. 조합마다 재고·추가금액·SKU를 다르게 줄 수 있습니다.

**추가금액**

옵션에 붙는 금액은 기본가에 **더해집니다**. 29,000원 상품에 XL 추가금 2,000원 → XL은 31,000원.

**비과세 금액**

판매가 중 부가세가 면제되는 금액입니다. 판매가를 넘을 수 없습니다.

**할인 타입 (헷갈리는 부분)**

`1 = 정률(%)`, `2 = 정액(원)` 입니다. 직관과 반대이니 Claude가 잘못 넣었다면 지적해 주세요.

**상세설명 타입 (`content_type`)**

| 값 | 뜻 |
|---|---|
| `1` | 양식(입력) |
| `2` | 이미지 |
| `3` | HTML |
| `4` | **블록 에디터 (권장)** |

보통은 신경 쓸 필요가 없습니다. 블록으로 채우면 자동으로 `4`, HTML만 넣으면 `3`이 됩니다.
`4`가 아니면 블록은 저장되지 않고 조용히 버려집니다.

**상세설명 블록 9종**

| 블록 | 쓰임 |
|---|---|
| 제목(`heading`) | 구간을 나누는 소제목 |
| 본문(`text`) | 설명 문단 |
| 사진(`image`) | 사진 여러 장. 세로 쌓기 / 2열 / 3열 |
| 사진+글(`imageText`) | 사진 옆(또는 위아래)에 설명 |
| 특징 카드(`features`) | 자랑할 점 3~4개를 카드로. **최대 4개** |
| 스펙 표(`specs`) | 소재·용량처럼 항목/값 표 |
| 안내 박스(`notice`) | 세탁법·신선식품 주의 등. 공용 블록 참조 가능 |
| 직접 HTML(`html`) | 기존 HTML을 그대로 넣을 때 |
| 구독 회차 표(`subscriptionPlan`) | 회차 설정에서 자동으로 채워지는 표 |

본문에는 **굵게·기울임·밑줄·글자 크기·링크·줄바꿈**만 남습니다. 그 밖의 태그는 저장할 때 제거됩니다.
문단을 나누려면 본문 블록을 여러 개 쓰세요.

**자동으로 채워지는 값 (토큰)**

`{{상품명}}` `{{판매가}}` `{{배송비}}` 를 상세설명에 넣어두면 저장할 때마다 실제 값으로 바뀝니다.
가격을 바꿔도 상세설명을 따로 고칠 필요가 없습니다. 할인 중이면 할인 적용가가 들어갑니다.

**상품 타입**

`0` 기본 · `1` 실물(배송) · `2` 콘텐츠(디지털) · `3` 모바일쿠폰 · `4` 예약 · `5` 온라인강의 · `7` 기부/펀딩 · `8` 세미나

`6`은 없습니다. 기부는 `7`, 강의는 `5`입니다.

**환불 관련 설정은 두 가지 (헷갈리는 부분)**

이름이 비슷하지만 **완전히 다른 것**입니다. 섞어 쓰지 마세요.

| | 환불정책 노출 | 디지털 환불 기준 |
|---|---|---|
| 대상 | 실물·디지털 **모든 상품** | **디지털 상품만** |
| 하는 일 | 상세페이지에 취소·반품·교환 정책을 어떻게 보여줄지 | 다운로드/접속 전후로 환불이 되는지 |
| 값 | `0` 쇼핑몰 정책 그대로(기본) / `1` 이 상품만 직접 작성 / `2` 노출 안 함 | 파일·링크 각각 "받기 전까지 가능" / "한 번이라도 받으면 불가" |

```
이 상품만 환불정책 따로 써줄게. "개봉 후 교환 불가"로 해줘
```

**결제폼 열기 방식**

단일 상품 랜딩 페이지에서 결제창을 언제 띄울지 고를 수 있습니다.

`0` 상품 페이지를 먼저 보여주고 버튼을 누르면 결제폼(기본) · `1` 들어오자마자 결제폼 · `2` 하단 시트 · `3` 외부 임베드 버튼

## 6. 사진 준비 요령

- **정사각형 권장** — 목록·썸네일에서 잘리지 않습니다.
- **1000×1000px 이상** — 확대해도 뭉개지지 않습니다.
- **대표 이미지 3장 내외**, 상세 이미지 3~6장이 무난합니다.
- 파일명에 확장자가 꼭 있어야 합니다. (`tshirt` ❌ / `tshirt.jpg` ✅)

MCP는 사진을 보정하거나 크기를 조절하지 않습니다. 올린 그대로 쇼핑몰에 나갑니다.

## 7. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 상품 관련 도구가 아예 안 보임 | HTTP로 연결됨 (Docs 도구만 보임) | [1번 설치](#1-설치)대로 `npx @bootpay/mcp` stdio 방식으로 다시 설정 |
| 설정을 바꿨는데 그대로임 | 앱 재시작 안 함 | Claude Desktop을 **완전히 종료** 후 재실행 (창 닫기 ❌) |
| `인증이 필요합니다` | 로그인 안 됨 / 토큰 만료 | `부트페이에 로그인해줘` |
| `프로젝트가 선택되지 않았습니다` | 쇼핑몰 미선택 | `프로젝트 선택할게` |
| `파일을 찾을 수 없습니다` | 경로 오타, 파일 이동 | Finder/탐색기에서 경로를 다시 복사. `~`는 그대로 써도 됩니다 |
| `지원하지 않는 확장자입니다` | 이미지가 아니거나 `.svg` | `.jpg .png .webp` 등으로 변환. SVG는 지원하지 않습니다 |
| `파일이 너무 큽니다` | 10MB 초과 | 이미지를 줄여서 다시 시도 |
| `한 번에 최대 10장` | 11장 이상 요청 | 나눠서 요청 |
| 상품은 만들어졌는데 쇼핑몰에 없음 | 임시저장 상태이거나 전시가 꺼져 있음 | `그 상품 발행해줘` / `그 상품 전시 켜줘` |
| 임시저장으로 만들었는데 쇼핑몰에 보임 | 임시저장이 반영되지 않음 (응답에 경고가 붙습니다) | `그 상품 전시 꺼줘` |
| 구독 상품인데 회차 가격이 안 보임 | 회차 조건 불일치 | 약정 구독이면 기간 1 이상, 무제한이면 -1. Claude가 미리 걸러 알려줍니다 |
| 상세설명을 채웠는데 안 보임 | 상세설명 타입이 블록(`4`)이 아님 | `상세설명을 블록으로 바꿔줘` |
| 상세설명 일부가 빠짐 | 템플릿 빈칸을 채우지 않고 저장 | 빈 블록은 상세에서 제외됩니다. 내용을 채워 다시 저장 |
| 상세설명이 통째로 사라짐 | "다 지워줘"로 전부 비움 | 되돌릴 수 없습니다. 다시 작성하세요 |
| 상세설명 사진이 안 나옴 | 로컬 파일 경로를 그대로 넣음 | 이미지를 먼저 업로드해 CDN 주소를 받아야 합니다. Claude가 미리 걸러 알려줍니다 |
| 상세설명에 굵게·표가 안 먹힘 | 허용되지 않은 태그 | 본문은 굵게·기울임·밑줄·링크만 됩니다. 표는 스펙 표 블록을 쓰세요 |
| 디지털 상품인데 지급이 안 됨 | 코드풀이 비었거나 지급 방식 미설정 | `시리얼 재고 얼마나 남았어?`로 확인 후 코드 등록 |
| `이미 등록된 코드` | 코드 목록에 중복이 섞임 | 하나라도 겹치면 전체가 거부됩니다. 기존 목록을 확인해 겹치는 값을 빼고 다시 등록 |
| `자동결제 동의 문구는 수시결제 전용` | 구독 유형이 수시결제가 아님 | 동의 문구를 빼고 저장하거나 구독 설정을 수시결제로 변경 |
| `구독 설정을 찾을 수 없습니다` | 잘못된 구독 설정 ID | `구독 설정 목록 보여줘`로 다시 확인 |
| `배송정책을 찾을 수 없습니다` | 잘못된 배송정책 ID | `배송정책 목록 보여줘`로 다시 확인 |
| 엉뚱한 쇼핑몰에 등록됨 | 프로젝트 선택 착오 | `부트페이 로그인 상태 알려줘`로 확인 후 다시 선택. 잘못 올린 상품은 삭제 |
| 브라우저가 안 열림 | 자동 실행 실패 | Claude가 알려주는 주소를 직접 복사해 브라우저에 붙여넣기 |

## 8. 용어 사전

| 용어 | 뜻 |
|---|---|
| 프로젝트 | 쇼핑몰 하나. 상품·주문·결제 설정이 프로젝트 단위로 나뉩니다 |
| 가맹점 | 사업자 단위. 하나의 가맹점 아래 여러 프로젝트를 둘 수 있습니다 |
| 전시 | 쇼핑몰 목록에 상품이 보이는지 여부 |
| 판매 | 장바구니 담기·결제가 가능한지 여부 |
| 임시저장 | 쇼핑몰에 노출되지 않는 작성 중 상태 |
| 옵션 조합 | 색상×사이즈처럼 선택지를 곱해 만든 개별 판매 단위 |
| 추가금액 | 옵션 선택 시 기본가에 더해지는 금액 |
| 비과세 금액 | 판매가 중 부가세가 면제되는 부분 |
| 카탈로그 | 상품을 진열하는 묶음. 카테고리(분류)와는 다른 개념입니다 |
| 구독 설정 | 결제 주기·약정 기간을 정해둔 템플릿. 구독 상품이 이걸 참조합니다 |
| 배송정책 | 배송비 계산 규칙. 상품이 이걸 참조합니다 |
| CDN 주소 | 업로드된 이미지가 서비스되는 인터넷 주소 |
| 상세설명 | 상품 페이지를 스크롤하면 나오는 긴 설명. 블록을 쌓아 만듭니다 |
| 블록 | 상세설명을 이루는 조각. 제목·본문·사진·특징 카드·스펙 표·안내 박스 등 |
| 빈칸 안내(hint) | 템플릿이 알려주는 "여기에 이런 내용을 쓰세요". 고객 화면에는 나가지 않습니다 |
| 공용 블록 | 여러 상품이 함께 쓰는 안내문. 한 곳을 고치면 쓰는 상품이 모두 바뀝니다 |
| 토큰 | `{{상품명}}` `{{판매가}}` `{{배송비}}` — 저장할 때마다 실제 값으로 바뀌는 자리 |
| 코드풀 | 디지털 상품에서 구매자마다 하나씩 나눠줄 시리얼 번호 재고 |
